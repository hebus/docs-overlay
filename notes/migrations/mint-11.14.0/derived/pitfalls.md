# Pitfalls, and the checks that catch them

Derived from every `kind: "pitfall"` entry. `Detectable by` is the refusal or diagnostic the tool
should carry, so the next person meets an error message instead of the pitfall.

| # | Phase | Pitfall | Workaround | Detectable by |
|---|---|---|---|---|
| 1 | setup | The dispositif that guarantees a journal is kept at the wall has to exist before the first step, and setting it up is itself a step. Bootstrapping it silently would make the first entries indistinguishable from reconstructed ones. | Declare the bootstrap window explicitly as entry 1, and re-derive every figure in entries 2-8 from a re-run command rather than from memory. | A migration command should write its own first journal entry before touching anything, so the window never exists. `check-journal.mjs` cannot detect this on its own — hence the declaration. |
| 3 | setup | A topic branch created from a remote branch inherits that remote branch as upstream. A bare `git push` on it can then target a protected release branch instead of a branch of the same name. | `git branch --unset-upstream` immediately after creating the worktree, verified with `git rev-parse --abbrev-ref @{u}` returning a fatal error. | `git rev-parse --abbrev-ref --symbolic-full-name @{u}` resolving to something other than a branch of the same name. |
| 5 | detect | `git ls-files --eol` output is `i/<eol> w/<eol> attr/<attrs>\t<path>`, and the attribute field itself contains spaces (`attr/text=auto eol=lf`). Splitting on whitespace yields an attribute fragment instead of the path, silently — the counts still look plausible. | Split on TAB for the path and only split field 1 on whitespace for the eol values. | A per-tree breakdown whose group names are not paths, or whose total does not match the overall count. |
| 7 | setup | Under Git Bash on Windows, paths passed to a native git.exe through stdin are not converted from MSYS form (/c/...) to Windows form (C:/...). The failure names existing files as missing, which sends you looking for a copy bug that is not there. | Convert with `cygpath -m` before writing paths to stdin, or keep paths repository-relative. | A `could not open ... No such file or directory` on a path that `test -f` confirms exists. |
| 8 | detect | git does not track directories, so an empty directory tree occupying a migration target is invisible to `git status`. A clean-tree check therefore does not prove the target paths are free. | Deleted the skeleton in the sibling worktree with `rm -rf`; nothing to commit, since git never tracked it. | An explicit `existsSync(target)` on every destination path, refused independently of the clean-tree check. |
| 10 | classify | A filename change alone can drag a weighted rename score under the accept threshold: content 1.00 on a 397-line line-identical body still landed at 0.700 because stem scored 0.00, so the strongest content evidence available produced a human question. | Added a branch evaluated before the weighted comparison: accept as a rename when content >= 0.95 and the runner-up's content is < 0.5. The uniqueness guard is what stops a genuinely duplicated page from being read as a move. | Any vanished slug whose best candidate has content >= 0.95 while the weighted score falls below the accept threshold -- that combination means the weights, not the evidence, decided. |
| 12 | setup | The formatter guard added in cee058eb is untested in this worktree: with no .husky/_ the pre-commit hook never fires, so nothing here can demonstrate that the guard stops oxfmt from rewriting a staged sidebars.json. It only takes effect for someone who has installed dependencies. | None needed for the migration itself, since no hook ran at any point; the guard was kept anyway because it matters for everyone else. | test -d "$(git config core.hooksPath)" |
| 14 | move | Rename detection pairs on content, not on source tree. Moving two trees that share byte-identical files in a single commit makes git attribute files to the wrong origin, so the commit stops documenting what it actually did even though the resulting tree is correct. | git reset --hard, then split into two commits ordered base-tree-first (11.13.0, then 11.14.0), so the base tree is already in HEAD and cannot be a rename candidate for the second. Verified afterwards with git diff --cached -M --summary \| grep -c 'docs =>' returning 0 on both. | After staging a move, grep the rename summary for a source path belonging to a tree the commit is not supposed to be moving: git diff --cached -M --summary \| grep -c 'docs =>' |
| 24 | detect | The claim was too broad. Renormalisation is confined to paths new to the index, which is precisely what a move creates, and precisely why git mv is mandatory here; it is also why adding overlay: blocks to five already-tracked files, three of them stored with CRLF, was safe and produced +2/-0 each. Believing the broad version would have made the safe edits look dangerous and made copy-then-add look no worse than git mv. | Use git mv for moves so no new index path is created; ordinary edits of already-tracked files need no precaution. | git ls-files --eol <path> before and after staging, or the 'CRLF will be replaced by LF' warning git prints on add. |
| 26 | wrapup | The rule that a journal entry ships in the same commit as the step it describes cannot hold across two repositories, so the usual proof that an entry was written at the wall rather than reconstructed afterwards is unavailable here. | Record repo_head on every entry and run check-journal.mjs --repo <migrated repo>, so the git cross-check replaces same-commit shipping as the anchor. | A journal whose entries all share one repo_head while the migration spans several commits. |
| 27 | build | Had the frontmatter schema been strict instead of .unknown(), stripping the overlay: block would have had to be the default, and every copied page would have become a rewrite -- losing its line endings, encoding and MDX imports as a side effect of a validation rule. | None needed; withoutOverlayBlock() is exported for a caller who would rather not ship the directive to the built site. | A site build failing with a frontmatter validation error naming overlay. |
| 28 | build | Counting a stub as a page makes the slug it occupies look alive to the sidebar merger, so pruneMissing() keeps a tombstoned entry and the rename rewrite never fires -- the sidebar then points at a redirect or at an unlisted 'removed in' page instead of the real one. | Stubs are deliberately excluded from docIds and dirNames -- a stub is a route, not a page. | A sidebar that still names a slug getEntries() reports as deleted or redirect. |
| 29 | build | An architecture check that reads sources as text cannot tell an import from a string that merely contains one, so it reported a violation the package does not commit; exempting the file wholesale would have stopped checking the one module most likely to reach for Docusaurus. | Strip template literals before scanning, plus a second test ('still sees an import that hides outside a template literal') proving the stripper does not swallow a real import sitting outside one -- guarding the guard. | An architecture check that reports a violation in a file whose only match is inside a string literal. |
| 30 | build | The shorter fix -- adding Node's types to the adapter's src project -- would have put process, Buffer and node:fs in scope for src/, so 'this adapter performs no I/O' would have become a stated intention instead of a checkable claim: a stray readFileSync in src/ would then compile without complaint. | A separate test project declaring types: ["node"], keeping Node's ambient types out of src/ entirely; the root typecheck script runs tsc -p packages/adapters/docusaurus/test alongside the src project. | npm run typecheck |
| 34 | config | `import.meta` in a Docusaurus config file is a compile-time SyntaxError, including in dead code, because jiti transpiles the config to CJS and runs it under `vm.Script`. Both occurrences had to be found by running the build; the second one hid in the text of an error message. | Used `__dirname`, which jiti's output provides, falling back to `process.cwd()` so a direct `import()` of the module still resolves its own directory. | grep the whole config chain for `import.meta` before building -- the build error names the file and the line, but reads as a module-format problem rather than a jiti one, so it does not point at the rule. |
| 35 | config | A `require.resolve()` call carried over from the CommonJS config broke the ESM shared base as soon as the two site configs imported it. | Passed the plugin name as a plain string and relied on Docusaurus resolving plugin names against the site directory. | `ReferenceError: require is not defined in ES module scope` when loading the config; equivalently, grep the config chain for `require(` or `require.resolve(` once any config file is ESM. |
| 38 | build | MSYS argument conversion under Git Bash silently turned a URL path flag into a Windows filesystem path. Because the value is only interpolated into generated links, the run succeeded and wrote ten pages with a poisoned URL instead of failing. | The CLI refuses a value shaped like a Windows path and prints the per-flag form `MSYS2_ARG_CONV_EXCL='--route-base-path=' docs-overlay ... --route-base-path=/`, naming why `'*'` is the wrong answer: excluding everything also stops `--site-dir` being converted, which then reaches Node as an unresolvable /c/... path. It also points at running the command from a package.json script, where no conversion happens. | reject any URL-valued flag whose value matches `^[A-Za-z]:[/\\]` -- the regex the CLI now applies is `/^[A-Za-z]:[/\\]\|\\/`. |
| 40 | build | Hoisting a React hook call into an MDX `export const` puts it at module level, outside any component, which React rejects -- so all 10 generated redirect stubs failed static site generation. | Called `useBaseUrl` inline in each JSX expression instead of hoisting it: same hook, same order, every render. | SSG failing for exactly the set of generated pages, and for no others -- a failure set equal to the stub set points at the template rather than at the content. |
| 43 | wrapup | Two of the migration's own claims were false: that the documentation site had no CI, and that the network was down. The first understated what existed; the second declared a whole capability unavailable on the strength of one failed command against one internal host, and would have skipped the build that found four defects. | Amended both commit messages before pushing. Verify a network claim with a command whose output you read, not whose exit code you trust, and scope the claim to the host that actually failed. | `nslookup` reporting NXDOMAIN while exiting 0 -- read its output, or use `getent hosts` or a real fetch against a public host before concluding anything about the network. For the CI claim: list the workflow files and read their `on:` triggers rather than inferring from pipeline behaviour. |
